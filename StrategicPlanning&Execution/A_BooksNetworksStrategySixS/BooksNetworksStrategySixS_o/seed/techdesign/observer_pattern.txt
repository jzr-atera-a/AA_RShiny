design_id: seed_observer_pattern
design_group: software_patterns
design_type: observer_pattern
title: Observer Pattern
variant: Push model with subject and observers
summary: Observer defines a one-to-many dependency so that when one object changes state, all its dependents are notified and updated automatically. The subject knows only the observer interface, so subjects and observers stay loosely coupled.
when_to_use: A change in one object must update an open-ended set of others, as in event systems, UI bindings and notifications.
when_not_to_use: There are few fixed dependents or updates must happen in a strict transactional order.
complexity: Low
tags: behavioral, gof, observer, events, pub-sub

@tradeoff
kind: pro
text: Loose coupling between subject and observers.

@tradeoff
kind: pro
text: Observers can be added or removed at runtime.

@tradeoff
kind: con
text: Notification order is not guaranteed.

@tradeoff
kind: con
text: Observers that are never detached leak memory.

@tradeoff
kind: risk
text: Cascading updates can cause loops or performance problems.

@tradeoff
kind: cost
text: Notification overhead grows with the number of observers.

@tradeoff
kind: scaling
text: Use asynchronous queues or an event bus when observers are many or remote.
