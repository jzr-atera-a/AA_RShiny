design_type: adapter_facade_pattern
title: Adapter and Facade Patterns
variant: Wrapping a legacy API and simplifying a subsystem
summary: Adapter converts the interface of an existing class into the one clients expect, letting incompatible classes work together. Facade provides one simple entry point to a complex subsystem. Both wrap existing code, but Adapter changes an interface while Facade simplifies it.
when_to_use: You must integrate a legacy or third-party class with a different interface, or hide a complex subsystem behind a simple API.
when_not_to_use: You control all the code and can change the interfaces directly.
complexity: Low
tags: structural, gof, adapter, facade, integration

@tradeoff

@tradeoff
kind: pro
text: Hides complexity and reduces coupling to subsystems.

@tradeoff

text: Adds an extra layer of indirection.

@tradeoff
kind: con

@tradeoff
kind: risk
text: Adapters hide mismatches in behaviour such as error handling or units.

@tradeoff

@tradeoff
kind: scaling
