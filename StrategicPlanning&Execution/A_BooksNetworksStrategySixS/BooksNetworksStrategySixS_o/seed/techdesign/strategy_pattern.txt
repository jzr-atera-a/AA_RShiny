design_type: strategy_pattern
title: Strategy Pattern
variant: Interchangeable algorithms behind an interface
summary: Strategy defines a family of algorithms, puts each in its own class behind a common interface and makes them interchangeable. The context holds a reference to a strategy and delegates the work, so the algorithm can be chosen or swapped at runtime.
when_to_use: Several variants of an algorithm exist, such as pricing, routing or sorting rules, and you want to switch them without conditionals.
when_not_to_use: The algorithm never changes or there are only two trivial variants.
complexity: Low
tags: behavioral, gof, strategy, polymorphism

@tradeoff
kind: pro
text: Removes large conditionals and isolates each algorithm.

@tradeoff
kind: pro
text: Strategies can be swapped at runtime and tested alone.

@tradeoff
kind: con
text: Clients must know the differences to choose a strategy.

@tradeoff
kind: con

@tradeoff
