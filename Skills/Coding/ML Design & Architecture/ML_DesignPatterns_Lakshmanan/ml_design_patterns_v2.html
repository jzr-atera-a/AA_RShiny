Hashed Features
DP-01
 Handles very high-cardinality categoricals (millions of user/product IDs) without a fixed vocabulary by mapping values to a finite set of hash buckets.
E-commerce product IDsURL classificationUser session trackingSearch query tokenisation
Wide & Deep NetworksLogistic RegressionGradient Boosted Trees
Fixed memory footprintNo pre-built vocabularyGraceful unseen-value handlingDeterministic & fast
Hash collisions reduce accuracyNot interpretableBucket size requires tuning
Low
→Embeddings (learn from hash)
→Hyperparameter Tuning (bucket sz)
→Repeatable Splitting (fingerprint)
Embeddings
DP-02
 Maps high-cardinality items to dense low-dimensional vectors encoding semantic similarity, allowing models to generalise across related entities.
Word2Vec / BERT NLPRecommendation systemsImage feature extractionGraph node representations
Neural Networks (DNN)Transformers (BERT / GPT)AutoencodersMatrix Factorization
Encodes semantic similarityReduces dimensionalityReusable across tasksHandles sparsity well
Requires large training dataDimension is a hyperparameterCold-start problem
Medium
→Feature Store (store & reuse)
→Transfer Learning (pre-trained)
→Hyperparameter Tuning (dim size)
Feature Cross
DP-03
 Explicitly creates interaction terms between features so linear models can learn non-linear relationships they otherwise cannot discover.
Ad CTR: city × device typeFare pricing: time × routeRetail: season × category
Linear / Logistic RegressionWide & Deep NetworksDecision Trees (implicit)
Boosts linear model accuracyEncodes domain knowledgeComputationally cheap
Combinatorial explosion riskManual engineering requiredUse Embeddings to mitigate
Low–Med
→Embeddings (avoid explosion)
→Hashed Features (cross + hash)
Multimodal Input
DP-04
 Combines heterogeneous data types (text, images, tabular, audio) into a single model, leveraging richer signal from diverse sources.
Medical: image + patient notesProduct: photo + descriptionVideo understanding: frames + audio
Multi-input DNNsCLIP / Multimodal TransformersFusion Networks
Leverages all available signalsOutperforms single-modalityRobust to missing modalities
Complex architectureData alignment challengesHigher training cost
High
→Transform (per-modality pre-proc)
→Embeddings (per modality)

Reframing
PR-01
 Transforms the problem formulation (e.g. regression → classification) to better match the loss landscape and dataset characteristics, improving handling of edge cases.
Fraud: regression → classificationDemand as ordinal rankingAge estimation as ordinal class
Classifiers (XGBoost, DNN)Ranking Models (LambdaMART)Ordinal Regression
Improves rare-case handlingUnlocks better loss functionsSimplifies evaluation

→Cascade (rare cases)
→Fairness Lens (bias check)
Multilabel
PR-02
 Addresses classification where each example can belong to multiple classes simultaneously, requiring independent sigmoid outputs per label rather than a single softmax.
Document tagging (news categories)Medical: multiple diagnosesImage scene labelling
DNN with Sigmoid outputsBERT fine-tunedRandom Forest (OvR)
Single model replaces manyLabel correlations learnedEfficient inference

 Combines predictions from multiple diverse models via bagging, boosting, or stacking to reduce variance/bias and produce more robust results than any single model.
Kaggle competition winnersCredit scoring (stability)Weather forecast ensembles
Random Forests (bagging)XGBoost / LightGBM (boosting)Stacked meta-learners
Reduces overfittingIncreases confidenceQuantifies uncertainty
Slower inferenceHigher compute & memoryNeeds Explainable Predictions

Cascade
PR-04
 Chains multiple specialised models in sequence; earlier models gate or route data to later models, efficiently handling subpopulations and hierarchical decisions.
Two-stage detection (YOLO → Refine)Email: spam filter → topicMedical: screening → diagnosis

Neutral Class
PR-05
 Adds an explicit "uncertain / neutral" category to capture ambiguous examples at class boundaries, reducing forced-choice misclassification in noisy or subjective domains.
Sentiment: +ve / neutral / −veIntent: matched / unclear / noneReview moderation systems
Softmax Classifiers (3-class)BERT / RoBERTa fine-tuned
Handles label ambiguityReduces forced-choice errorsImproves confidence calibration
Neutral boundary must be definedBias can shift to neutral bucketHigher annotation cost
Low–Med
→Reframing (problem framing)
→Cascade (uncertain routing)
Rebalancing
PR-06
 Corrects class imbalance via oversampling (SMOTE), undersampling, or cost-sensitive weighting so models don't ignore minority classes like fraud or rare diseases.
Fraud detection (1:1000 ratio)Rare disease detectionManufacturing defect ID
XGBoost (scale_pos_weight)SVM (class_weight param)DNN (weighted loss function)
Improves minority class recallMultiple complementary techniquesUse all data via Ensembles
Oversampling can overfit minorityUndersampling loses majority dataThreshold selection is tricky
Medium
→Ensembles (use all data)
→Explainable Predictions
→Cascade & Reframing

Stateless Serving Function
RS-01
 Designs inference endpoints with zero server-side session state — all context passed in the request — enabling horizontal scaling, fault tolerance, and reproducible responses.
REST API model endpointsCloud Functions / Lambda servingMicroservice ML inference
TF Serving / TorchServeFastAPI + ONNXVertex AI Endpoints
Infinitely horizontally scalableZero-downtime deploymentsReproducible per request
All context in each requestLarger request payloadsTradeoff with Model Versioning
Low–Med
→Model Versioning (alt approach)
→Batch Serving (throughput tradeoff)
→Transform (bake into serving)
Batch Serving
RS-02
 Pre-computes and caches predictions for all known inputs offline, trading response latency for throughput where predictions cover a fixed, queryable set of items.
Nightly recommendation pre-computeRisk score batch runs (banking)Product ranking for search index
Any model (inference phase)Spark MLlibBigQuery ML PREDICT
Very low serving latency (cache hit)High GPU/CPU utilisationPredictable infrastructure cost
Predictions can be staleCannot handle novel inputs at serve timeStorage overhead
Low–Med
→Windowed Inference (ordered inputs)
→Keyed Prediction (distributed)
→Stateless Serving (latency tradeoff)

All production modelsEvidently AI / SeldonVertex AI Model Monitoring
Early detection of model degradationAutomated retraining triggersData quality monitoring
Requires ground truth labels (delayed)Alert fatigue if thresholds wrongNeeds live labelling infrastructure

→Model Versioning (compare)
→Fairness Lens (incorporate)
→Workflow Pipeline (retrain trigger)
Two Phase Predictions
RS-04
 Splits inference into a fast lightweight Phase 1 (coarse retrieval/filtering) and a precise Phase 2 (expensive reranking), balancing latency with quality at billion-item scale.
Recommendation: recall → rankingSearch: BM25 → neural rerankerAds: retrieval → auction scoring
ANN (FAISS / ScaNN) + DNNBM25 + BERT rerankerLogistic Regression + XGBoost
Scales to billions of candidatesQuality via expensive final rankerEach phase independently tunable
Phase 1 recall ceiling limits Phase 2Complex system design & monitoringTwo training datasets needed
High
→Windowed Inference (batch phase)
→Keyed Prediction (within phase)
→Cascade (structural similarity)
Keyed Prediction
RS-05
 Attaches a client-provided passthrough key to each prediction request that is returned with the response, enabling correct reassembly of results in async distributed batch pipelines.
Distributed batch scoring pipelinesAsync ML API result correlationMulti-tenant prediction services
Batch APIs (Vertex AI, SageMaker)TF Serving with metadata passthrough
Parallel async batch inferenceCorrect reassembly at scaleWorks with out-of-order responses
Keys must be unique & managedAdds payload overhead
Low–Med
→Batch Serving (required for distributed)
→Continued Model Evaluation (required)

 Establishes a simple rule-based or statistical baseline that any ML model must demonstrably outperform before deployment is justified, preventing over-engineering of already-solved problems.

Prevents unnecessary ML complexityRapid to implement & communicateCreates ML accountability

Regulatory complianceReveals bias & data issuesBuilds stakeholder trustAids complex model debugging

Transfer Learning
TL-01
 Leverages representations from a large general model and fine-tunes them for a domain-specific task, drastically reducing labelled data and compute requirements.
BERT fine-tuned for legal NLPImageNet → medical imagingGPT fine-tuned for code completionResNet → satellite image analysis
BERT / GPT / T5 (NLP)ResNet / EfficientNet (Vision)Whisper (Audio)
Far less labelled data neededFaster convergenceState-of-the-art baselines easilyEmbeds domain knowledge
Negative transfer if domains differLarge model memory footprintCatastrophic forgetting risk
Medium
→Embeddings (a form of)
→Checkpoints (fine-tuning from)
→Cascade (might require)
Useful Overfitting
TL-02
 Deliberately trains a model to perfectly memorise a small, deterministic dataset — appropriate when exact memorisation is desired (physics simulators, lookup tables) not generalisation.
Neural network ODE solversPhysics simulation surrogatesExact lookup table compression
Small DNNs / MLPsPhysics-Informed Neural NetworksNeural ODEs
Perfect accuracy on known dataCompresses complex functionsDifferentiable surrogate model
Zero generalisation to unseen inputsVery narrow applicable scenariosEasy to misapply — understand context
Low–Med
→Cascade (chained optimisation)
→Checkpoints (save memorised state)
Checkpoints
TL-03
 Periodically saves model weights during training, enabling recovery from failures, early stopping at optimal validation performance, and warm-starting fine-tuned variants.
Multi-day LLM pretraining recoveryEarly stopping for regularisationCurriculum learning staged training
All deep learning modelsTF ModelCheckpoint / PyTorch saveKeras callbacks
Resilient to training failuresEnables optimal early stoppingFoundation for Transfer LearningTraining schedule experimentation
Storage cost for large modelsSelection needs validation monitoring
Low
→Transfer Learning (fine-tuning from)
→Distribution Strategy (coordinate)
→Model Versioning (checkpoint = version)
Distribution Strategy
TL-04
 Distributes training across multiple GPUs/TPUs or machines using data/model/pipeline parallelism to reduce wall-clock time for large model and dataset training.
LLM training on TPU podsMulti-GPU ResNet (data parallel)Federated learning (edge devices)
TF MirroredStrategy / MultiWorkerPyTorch DDP / FSDPDeepSpeed / Megatron-LM
Enables billion-parameter model trainingNear-linear scaling (data parallel)Reduces training wall-clock time
Communication overhead (allreduce)Debugging across workers is hardLR / batch size rescaling required
High
→Checkpoints (required at scale)
→Hyperparameter Tuning (batch/LR rescale)
Hyperparameter Tuning
TL-05
 Automates the search for optimal model hyperparameters (learning rate, depth, embedding size, regularisation) using Bayesian optimisation, grid/random search, or neural architecture search.
Vertex AI Vizier / OptunaNAS for efficient architecturesHash bucket & embedding dim selectionEnsemble weight optimisation
Bayesian Optimisation (BO)Population-Based Training (PBT)Hyperband / ASHANeural Architecture Search (NAS)
Finds configs beyond human intuitionReproducible & loggableGenerator of Ensembles
Computationally expensiveRisk of overfitting to validation setRequires proper train/val/test discipline
High
→Embeddings (dimension choice)
→Hashed Features (bucket size)
→Ensembles (as generator)
→Bridged Schema (old examples)
